# RoweMod 3.3.9

Fixes a startup error when the game's generated equip coroutine wrapper is missing from its MelonLoader interop assembly.

- Prevents the missing `_EnumEquip_d__80` type from aborting RoweMod's remaining startup steps.
- Skips the affected custom-hair hook group when its wrapper is unavailable, with a diagnostic in the log.
- Checks the completion wrapper's properties before installing the custom-hair hooks.
- Preserves native game-build and hook-address checks. This release does not add native-hook support for unaudited game builds.

## Install

Replace `BMX Streets/Mods/rowemod.dll` with 3.3.9 while the game is closed, then restart. Existing customization files, presets, and emote downloads remain supported.

## Verification

The Release build, 156 automated checks, and compiled hook/signature audit passed. The missing-wrapper regression compiles an assembly with the equip coroutine omitted and verifies that the affected group skips while the remaining hook groups initialize.

A fresh local launch regenerated interop assemblies with `_EnumEquip_d__111` instead of `_EnumEquip_d__80`, then reached the main menu with RoweMod running and no `TypeLoadException`. Native-hook safety rejected the updated game binary: 0/7 late hook groups were available, and custom outfit materials timed out waiting for equip completion. Full native-hook and custom-outfit compatibility with this newer game build remains unverified and requires a separate native audit; this release fixes the startup abort.

The reporting user's game remains to be retested. Their complete `MelonLoader/Latest.log` is needed to confirm their game build and the earlier HangFive error.
